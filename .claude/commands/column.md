# コラム・読み物記事作成スキル（SHIFT AI AIライター講座準拠）

クラウドワークスでコラム・エッセイ・読み物記事を受注・作成するための執筆ガイドです。
SHIFT AI「AIライター Version2 記事作成」講座のメソッドを基にしています。

## 使い方

```
/column [テーマ] [媒体の雰囲気] [文字数]
```

例: `/column 在宅ワークの孤独感との向き合い方 共感系・30代女性向け 2000字`

---

## 全体フロー

```
STEP1 テーマ・方向性の設定
  └─ メッセージの核 → ペルソナ設定 → 媒体トーン把握
STEP2 構成案作成
  └─ 起承転結 / PREP法 / 問題提起型 から選択
STEP3 本文執筆
  └─ PREP法/SDS法 → 個性・視点 → AI生成文添削
STEP4 リード文・まとめ文作成
STEP5 品質チェック
  └─ AIっぽさ除去 → トンマナ確認 → コピペチェック
```

---

## STEP 1: テーマ・方向性の設定

### 記事の「核」を決める
$ARGUMENTS のテーマについて以下を明確にしてください。

```
伝えたいメッセージ（一言で）:
  例) 「完璧にやろうとしなくていい」「孤独は悪いことじゃない」

読後に読者に感じてほしいこと:
  □ 共感・「わかる！」
  □ 気づき・「そういう見方もあるか」
  □ 前向きな気持ち・「やってみよう」
  □ 笑い・「あるある」

独自の視点・切り口:
  （ありきたりでない、自分ならではの見方は何か？）
```

### ペルソナ・媒体の把握
```
ターゲット読者の属性（年齢・性別・ライフスタイル）:
読者が抱える悩み・興味・価値観:
媒体のトーン（フォーマル / カジュアル / 共感系 / ビジネス系）:
NGテーマ・NGワード（クライアント指定があれば）:
```

> AIを使う場合: ChatGPTに「[テーマ]について[ターゲット読者]に向けたコラムの切り口を5つ提案して」と入力する

## STEP 2: 構成案作成

### パターンA: 起承転結（エモーショナル・共感系）

```
【タイトル】（読者の感情に刺さる言葉を使う）
  例) 「完璧にやろうとするのをやめたら、仕事が楽しくなった話」

【書き出し（起）】
  → 具体的なシーン・情景描写から入る
  → 読者が「あるある」と感じる共感ポイント

【展開（承）】
  → 問題・矛盾・疑問の深掘り
  → 自分の体験や気づきを盛り込む

【転換（転）】
  → 視点の転換・意外な発見
  → 読者の予想を裏切る展開

【結び（結）】
  → メッセージを着地させる
  → 余韻を残す締め方（説教臭くしない）
```

### パターンB: PREP法（論理系・ビジネス系）

```
P（Point）   — 結論・主張を最初に述べる
R（Reason）  — その理由を説明
E（Example） — 具体例・データ・体験談で裏付け
P（Point）   — 結論を再度まとめる
```

### パターンC: 問題提起型（情報系・解決志向）

```
書き出し: 読者が「わかる！」と思う問題提起
  ↓
その問題の背景・原因を掘り下げ
  ↓
自分なりの解釈・視点を提示
  ↓
解決策 or 受け入れ方 or 新しい見方を提案
  ↓
前向きな締め
```

## STEP 3: 本文執筆

### 文章の型（コラムでの活用）

**PREP法**（主張を伝えるセクションに使う）
```
P（Point）   — 「私は○○だと思います」と主張
R（Reason）  — 「なぜなら〜」
E（Example） — 「たとえば、こんなことがありました」
P（Point）   — 「だから○○なんです」
```

**SDS法**（情報を整理するセクションに使う）
```
S（Summary） — 「このコラムのテーマは○○です」
D（Detail）  — 詳細・エピソード・根拠
S（Summary） — 「つまり〇〇ということです」
```

### 書き出しで心をつかむ

良い書き出しの例：
```
情景描写から入る:
  「梅雨の蒸し暑い夜、私はまた締め切りを前にPCを閉じた。」

問いかけから入る:
  「あなたは最後に"何もしない時間"を過ごしたのはいつですか？」

逆説から入る:
  「一番孤独を感じるのは、人混みの中にいるときだ。」

統計・事実から入る:
  「日本人の約4割が、日常的に孤独を感じているという。」
```

### コラムらしい「個性」を出す
- 書き手の視点・価値観を前面に出す（「みんなそう思ってる」ではなく「私はこう感じた」）
- 具体的なエピソード・数字・固有名詞を入れてリアリティを出す
- 意外な比喩・言い回しを使う
- 完璧な答えを出さなくていい（「〜かもしれない」という余白も大切）
- 抽象論だけで終わらせない（必ず具体例とセットにする）

### テンポとリズム
- 長い文の後には短い文を置く
- 感情が高まる場面は短文・体言止めを使う
- 読者に問いかける文を適度に入れる（「あなたはどうですか？」）
- 一段落は3〜5文を目安にする

### レギュレーション遵守
- **トンマナ統一**: 文体（です・ます調 / だ・である調）を記事全体で統一する
- **文章の長さ**: 指定文字数の±5%以内に収める
- **NGワード**: クライアント指定の禁止表現・テーマを避ける
- **「べき」「すべき」の多用禁止**: 押しつけがましくなる

### AI生成文の添削ポイント

| チェック項目 | 悪い例 | 良い例 |
|------------|-------|-------|
| 同じ文末の繰り返し | 〜です。〜です。〜です。 | 〜です。〜でした。〜ではないか。 |
| 上から目線 | 「〜すべきです」 | 「〜してみるのもいいかもしれません」 |
| 抽象的すぎる | 「大切にすることが重要です」 | 「毎朝5分だけ、手帳を開くようにしました」 |
| 説教臭い | 「〇〇を意識しましょう」 | 「私はこうするようにしています」 |
| AIらしい語尾 | 「〜しましょう」の多用 | 体言止め・問いかけ・倒置法を混ぜる |

## STEP 4: リード文・まとめ文

### リード文の書き方（150〜250字）
```
① 読者の悩み・共感ポイントに刺さる一文
② この記事を読むと何が得られるかを示す
③ 読み進める動機づけ
```

**構成例（共感系）**
```
「[読者が感じている悩みの描写]と感じたことはありませんか？
この記事では、[テーマ]について私自身の体験をもとにお伝えします。
[読後に感じてほしいこと]のヒントになれば幸いです。」
```

### まとめ文の書き方
- 記事のメッセージを一言で再提示する（説教にならない言葉で）
- 読者への問いかけや余韻のある一文で締める
- 行動を促す場合はさりげなく誘導する（「ぜひ試してみてください」程度）

## STEP 5: 品質チェック

### AIっぽさ除去チェック
- [ ] 同じ文末表現が3回以上連続していない
- [ ] 「〜ということ」「〜となっています」などの冗長表現がない
- [ ] 単調な接続詞（「また」「さらに」）の繰り返しがない
- [ ] 体言止め・問いかけ・倒置法などの表現バリエーションがある
- [ ] 「〜すべき」「〜べきです」の多用がない
- [ ] 読んで「人が書いた」と感じられる自然さがある

### トンマナ・内容チェック
- [ ] 書き出しの最初の一文が魅力的か
- [ ] 「で、結局何が言いたいの？」に答えられる核があるか
- [ ] 具体的なエピソードや場面が描かれているか
- [ ] 媒体のトーンと文体が合っているか
- [ ] 指定文字数の±5%以内に収まっているか
- [ ] 締め方に余韻・メッセージがあるか

### コピペチェック
- [ ] **CCDツール**でコピー率を確認する
- [ ] 他サイトの文章・エピソードを流用していない
- [ ] 引用する場合は出典を明記している

### ファクトチェック（統計・事実を使う場合）
- [ ] **Perplexity** または **Felo** で数値・統計を確認する
- [ ] 情報の発信元が信頼できるか確認する
- [ ] AIが生成した数値は必ず原典で裏取りする

## クラウドワークスで評価されるコラムのコツ

**発注者が求めているもの**
- ブランドや媒体の世界観に合った文体
- 読者がシェアしたくなる「刺さる」内容
- 修正が少なく済む完成度の高い初稿

**リピート受注につながる納品**
- 構成の意図を一言添えて納品する（「書き出しで共感を引き出し、後半で視点を転換させる構成にしました」）
- 発注者指示外でも気づいた点はコメントで提案する
- 修正依頼には素直に対応し、理由も聞いて次回に活かす
- レギュレーションがない案件では、自分でトンマナを設定して一貫性を保つ
