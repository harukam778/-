# SEO記事作成スキル（SHIFT AI AIライター講座準拠）

クラウドワークスでSEO記事を受注・作成するための執筆ガイドです。
SHIFT AI「AIライター Version2 記事作成」講座のメソッドを基にしています。

## 使い方

```
/seo-article [メインキーワード] [サジェストキーワード（任意）] [文字数]
```

例: `/seo-article 糖質制限 ダイエット 初心者 3000字`

---

## 全体フロー

```
STEP1 市場調査・リサーチ
  └─ キーワード整理 → ペルソナ設定 → 検索意図分析 → 上位記事分析
STEP2 構成案作成
  └─ h2/h3見出し設計 → キーワード配置 → オリジナリティ確保
STEP3 本文執筆
  └─ PREP法/SDS法 → AI生成文の添削 → トンマナ統一
STEP4 リード文・まとめ文作成
STEP5 品質チェック
  └─ AIっぽさ除去 → コピペチェック → ファクトチェック
```

---

## STEP 1: 市場調査・リサーチ

### キーワードの整理
$ARGUMENTS のキーワードを以下の3種類に整理してください。

- **メインキーワード**: 記事全体の主軸となるキーワード
- **サジェストキーワード**: 検索窓に入力すると表示される関連語（ラッコキーワードで抽出）
- **関連キーワード**: 検索結果ページ下部に表示される「関連する検索キーワード」

> ツール: **ラッコキーワード**（無料登録で利用可）でサジェスト・関連KWを一括抽出する

### ペルソナ・検索意図の設定
以下を明確にしてください。

```
ターゲット読者:
  - 属性（年齢・性別・職業・ライフスタイル）
  - 抱えている悩みや課題
  - 知識レベル（初心者 / 中級者 / 上級者）

検索意図（どれに当たるか）:
  □ 情報収集型 — 「〇〇とは？」「〇〇の方法」
  □ 比較検討型 — 「〇〇 おすすめ」「〇〇 比較」
  □ 購入・行動型 — 「〇〇 購入」「〇〇 申し込み」

記事のゴール（読者に何をしてほしいか）:
  例）商品購入 / メルマガ登録 / 問い合わせ / 別記事への回遊
```

> AIを使う場合: ChatGPTに「[キーワード]で検索するユーザーのペルソナと検索意図を分析して」と入力する

### 上位記事の分析
Google検索で対象キーワードを検索し、上位5〜10記事を以下の観点で分析してください。

- 共通して扱われているトピック（必ず含めるべき内容）
- 差別化できる切り口（上位記事にないオリジナル要素）
- 強調キーワード（太字になっている語句）
- 見出し（h2/h3）の構成パターン

## STEP 2: 構成案（目次）作成

5段階プロセスで構成案を作成してください。

```
① 上位記事の見出し構造を3〜5記事分メモする
② 共通トピックを洗い出し、必須セクションを決める
③ 差別化できるオリジナルセクションを追加する
④ h2・h3にキーワードを自然に盛り込む
⑤ 流れが読者にとって論理的か確認する
```

**構成フォーマット**

```
【タイトル】（32文字以内・メインKWを含む）
例: 「糖質制限ダイエットの始め方｜初心者が1週間で実感する5つのコツ」

【リード文】（後述）

H2: ○○とは？基本と仕組みを解説
  H3: ○○の定義
  H3: なぜ効果があるのか

H2: ○○の始め方・具体的な手順
  H3: STEP1 ○○
  H3: STEP2 ○○
  H3: STEP3 ○○

H2: ○○の注意点とよくある失敗
H2: ○○に関するよくある質問（FAQ）

【まとめ】
```

**キーワード配置のルール**
- タイトルにメインKWを必ず含める
- h2見出しに2〜3回メインKWを含める
- 本文のキーワード密度は2〜3%（詰め込みすぎない）
- **コピーコンテンツ防止**: 上位記事の見出しをそのままコピーしない。表現を変え、独自の切り口を加える

> AIを使う場合: ChatGPTに「[キーワード]のSEO記事の構成案をh2/h3形式で作成して。上位記事にない独自の視点も含めて」と入力する

## STEP 3: 本文執筆

### 文章の型（PREP法・SDS法）

**PREP法**（説得力のある主張に使う）
```
P（Point）    — 主張・結論を先に述べる
R（Reason）   — 理由を説明する
E（Example）  — 具体例・データ・体験談を示す
P（Point）    — 結論を再度まとめる
```

**SDS法**（情報をわかりやすく整理するときに使う）
```
S（Summary）  — 要約・全体像を先に述べる
D（Detail）   — 詳細を説明する
S（Summary）  — 再度まとめて理解を定着させる
```

### 読みやすい文章の4原則

1. **わかりやすさ** — 専門用語には必ず説明を加える。中学生でも理解できる言葉を選ぶ
2. **結論先出し** — 段落の最初に結論を書き、後から根拠・詳細を続ける
3. **短文化** — 一文は60字以内を目安にする。長い文は分割する
4. **箇条書き活用** — 3つ以上の要素は箇条書きにする。手順は番号付きリストにする

### AI生成文の添削ポイント

AIが出力した文章は必ず以下の観点で人の手で修正してください。

| チェック項目 | 悪い例 | 良い例 |
|------------|-------|-------|
| 同じ文末の繰り返し | 〜です。〜です。〜です。 | 〜です。〜でした。〜といえます。 |
| 冗長な表現 | 「〜ということになります」 | 「〜です」 |
| 抽象的すぎる表現 | 「非常に重要です」 | 「○○のために欠かせません」 |
| 不自然な接続詞 | 「また、また、また、」 | 接続詞を変化させる |
| AIらしい語尾 | 「〜しましょう」の多用 | 体言止め・問いかけなどを交える |

### レギュレーション遵守

クライアントから指示がある場合は必ず守り、ない場合は自作のレギュレーションを設定してください。

- **トンマナ（トーン&マナー）**: 文体（です・ます調 / だ・である調）を記事全体で統一する
- **文章の長さ**: 指定文字数の±5%以内に収める
- **禁止表現**: 「絶対に」「必ず効果がある」などの断定・誇大表現を避ける
- **医療・法律・金融**: 「専門家へのご相談をおすすめします」と注記する

## STEP 4: リード文・まとめ文

### リード文の書き方（200〜300字）

```
① 読者の悩み・ニーズに共感する一文
② この記事で解決できることを明示する
③ 読み進める動機づけ（記事のゴールへの誘導）
```

**構成例**
```
「[悩み・状況の共感]と悩んでいませんか？
この記事では、[メインKW]について[読者が得られること]を解説します。
[読み進めることで得られるメリット]ので、ぜひ最後までご覧ください。」
```

- リード文の最初の100字以内にメインキーワードを入れる
- 「結論から言うと〜」と先に答えを提示するのも効果的

### まとめ文の書き方

```
① 記事の要点を箇条書きで3〜5点整理する
② 読者への行動喚起（次のステップを提案する）
③ 関連記事・サービスへの誘導（クライアント指示がある場合）
```

## STEP 5: 品質チェック

### AIっぽさ除去チェック
- [ ] 同じ文末表現が3回以上連続していない
- [ ] 「〜ということ」「〜となっています」などの冗長表現がない
- [ ] 単調な接続詞（「また」「さらに」）の繰り返しがない
- [ ] 体言止め・問いかけ・倒置法などの表現バリエーションがある
- [ ] 読んで「人が書いた」と感じられる自然さがある

### コピペチェック
- [ ] **CCDツール**（https://ccd.cloud/）でコピー率を確認する（クライアント基準に合わせる、一般的に20%以下）
- [ ] 上位記事の表現をそのまま流用していない
- [ ] 引用する場合は出典を明記している

### ファクトチェック
- [ ] **Perplexity**（https://www.perplexity.ai/）または **Felo** で数値・統計・固有名詞を検索して確認する
- [ ] 情報の発信元が公的機関・専門機関・一次情報かを確認する
- [ ] AIが生成した数値・データは必ず原典で裏取りする（AIの数値は誤りが多い）
- [ ] 最新情報かどうか（記事公開年を確認）

### SEO・構成チェック
- [ ] タイトルが32文字以内でメインKWを含んでいる
- [ ] リード文の冒頭100字以内にメインKWがある
- [ ] h2見出しにキーワードが自然に盛り込まれている
- [ ] まとめ文がある

## 使用ツール一覧

| ツール | 用途 | 備考 |
|-------|------|------|
| **ラッコキーワード** | サジェスト・関連KW抽出 | 無料登録で月30回まで |
| **ChatGPT** | リサーチ・構成案・本文生成 | GPTs「雷PJ」活用も可 |
| **Perplexity** | ファクトチェック・情報収集 | 出典リンク付きで信頼性確認 |
| **Felo** | ファクトチェック補助 | Perplexityと併用する |
| **CCD** | コピペチェック | 1万字まで無料 |

---

## クラウドワークス納品時のポイント

- 構成の意図を一言添えて納品する（「検索意図は〇〇と判断し、この構成にしました」）
- Wordまたはテキスト形式の場合、見出しレベル（h2/h3）を明記する
- 修正依頼には理由を確認して次回に活かす
- レギュレーションがない案件では、自分でトンマナを設定して一貫性を保つ
