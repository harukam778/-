# 商品レビュー記事作成スキル

クラウドワークスで商品レビュー記事を受注・作成するための品質チェックと執筆ガイドです。

## 使い方

```
/product-review [商品名] [カテゴリ] [ターゲット読者]
```

例: `/product-review ルンバj7+ ロボット掃除機 共働き夫婦`

---

## 商品レビュー作成プロセス

### STEP 1: 商品リサーチ

$ARGUMENTS の商品について以下の情報を整理してください。

**基本情報**
- 商品名・メーカー・価格帯
- 主なスペック・機能
- ターゲット層（公式が想定する購買層）

**競合比較**
- 同価格帯の競合商品（2〜3つ）
- 差別化ポイント（何が優れているか / 劣るか）

**ユーザーの声（調査ポイント）**
- Amazonレビューで多い高評価の理由
- Amazonレビューで多い低評価・不満点
- SNS（X/Instagram）でのリアルな口コミ傾向

### STEP 2: 構成案作成

```
【タイトル案】
パターンA: 「○○レビュー｜実際に使ってわかった5つのメリットと注意点」
パターンB: 「○○は買って損なし？1ヶ月使った正直な感想」
パターンC: 「○○の口コミ・評判を徹底検証！購入前に知るべきこと」

【リード文】（200〜300字）
- こんな人に向けた記事（ターゲット明示）
- 結論を先出し（買うべきか否か）
- 読み進める価値を伝える

【本文構成】
H2: ○○の基本情報・スペック
H2: ○○を実際に使ってみた感想（良い点）
  H3: 良い点①
  H3: 良い点②
  H3: 良い点③
H2: ○○の気になる点・デメリット
  H3: デメリット①
  H3: デメリット②
H2: ○○はこんな人におすすめ / 向かない人
H2: 競合商品との比較
H2: よくある質問（FAQ）

【まとめ・総評】
- 5段階評価（コスパ・機能・デザイン・使いやすさ・総合）
- 購入をおすすめするターゲット
- 購入リンクへの誘導（アフィリエイト案件の場合）
```

### STEP 3: 執筆ルール

**信頼性を高める書き方**
- 実体験ベースで書く（「〜と感じました」「〜でした」）
- 良い点・悪い点を必ず両方書く（提灯記事にしない）
- 数値・スペックは公式サイトを確認して正確に記載
- 「個人の感想です」「効果には個人差があります」を必要に応じて記載

**読者が知りたい情報を優先**
- 購入を迷っている人の疑問に答える
- 「実際どうなの？」という本音の情報を盛り込む
- 使用シーン・使用頻度・家族構成など具体的な状況を描写

**比較表の活用**
```
| 比較項目 | ○○（本商品） | 競合A | 競合B |
|---------|------------|------|------|
| 価格    | ¥XX,000    | ¥XX,000 | ¥XX,000 |
| 機能A   | ◎          | ○    | △    |
| 機能B   | ○          | ◎    | ○    |
```

### STEP 4: 品質チェックリスト

**内容チェック**
- [ ] 商品の良い点と悪い点の両方を書いている
- [ ] スペック・価格が正確（公式サイト確認済み）
- [ ] 具体的な使用シーンが描かれている
- [ ] 「こんな人におすすめ」が明確になっている

**信頼性チェック**
- [ ] 根拠のない誇大表現がない
- [ ] 健康・美容商品の場合、効果効能の過度な主張がない
- [ ] 競合商品を不当に貶めていない
- [ ] アフィリエイトリンクがある場合、PR表記がある

**SEO・読みやすさチェック**
- [ ] タイトルに商品名とレビュー系キーワードが入っている
- [ ] リード文で結論（買うべきか）を伝えている
- [ ] 見出しが読者の疑問形になっている
- [ ] 箇条書き・比較表が適切に使われている

---

## クラウドワークス納品時の注意点

- PR・広告案件の場合は必ず冒頭に「PR」「広告」「プロモーション」と明記する
- 薬機法・景品表示法に違反する表現は使わない（特に美容・健康・サプリ）
  - NG例：「〇〇が治る」「絶対痩せる」「効果保証」
  - OK例：「〇〇が気になる方に」「すっきり感を実感」
- Amazonリンク等は発注者の指示に従って挿入する
