# 商品レビュー記事作成スキル（SHIFT AI AIライター講座準拠）

クラウドワークスで商品レビュー記事を受注・作成するための執筆ガイドです。
SHIFT AI「AIライター Version2 記事作成」講座のメソッドを基にしています。

## 使い方

```
/product-review [商品名] [カテゴリ] [ターゲット読者]
```

例: `/product-review ルンバj7+ ロボット掃除機 共働き夫婦`

---

## 全体フロー

```
STEP1 商品リサーチ
  └─ スペック整理 → 競合分析 → ユーザーの検索意図把握
STEP2 構成案作成
  └─ 上位記事分析 → h2/h3設計 → オリジナリティ確保
STEP3 本文執筆
  └─ PREP法/SDS法 → 良い点・悪い点を両方書く → AI生成文添削
STEP4 リード文・まとめ文作成
STEP5 品質チェック
  └─ AIっぽさ除去 → コピペチェック → ファクトチェック → 薬機法確認
```

---

## STEP 1: 商品リサーチ

### キーワード整理
$ARGUMENTS の商品に関連するキーワードを整理してください。

- **メインKW**: 「[商品名] レビュー」「[商品名] 口コミ」
- **サジェストKW**: ラッコキーワードで「[商品名]」を検索して抽出
- **検索意図**: 「買うべきか知りたい（比較検討型）」が中心

### 商品の基本情報整理
```
商品名・メーカー:
価格帯（定価・実勢価格）:
主なスペック・機能:
公式が想定するターゲット:
販売チャネル（Amazon / 公式サイト / 店舗）:
```

### 競合・市場分析
Google検索で「[商品名] レビュー」「[商品名] 口コミ」を検索し、上位記事を分析してください。

- 上位記事が共通して扱っているトピック（必須セクション）
- 差別化できる切り口（上位記事にない独自要素）
- Amazonレビューで多い高評価・低評価の理由
- SNS（X/Instagram）でのリアルな口コミ傾向

> AIを使う場合: Perplexityで「[商品名]のメリット・デメリット 口コミ」を検索して情報収集する（出典リンクで信頼性確認）

## STEP 2: 構成案作成

**タイトル案（パターン別）**
```
A) 「[商品名]レビュー｜実際に使ってわかった5つのメリットと注意点」
B) 「[商品名]は買って損なし？1ヶ月使った正直な感想」
C) 「[商品名]の口コミ・評判を徹底検証！購入前に知るべきこと」
```

**構成フォーマット**
```
【リード文】（後述）

H2: [商品名]の基本情報・スペック
H2: [商品名]を実際に使ってみた感想（良い点）
  H3: 良い点① ○○が便利
  H3: 良い点② ○○が優秀
  H3: 良い点③ ○○の満足度が高い
H2: [商品名]の気になる点・デメリット
  H3: デメリット① ○○
  H3: デメリット② ○○
H2: [商品名]はこんな人におすすめ / 向かない人
H2: 競合商品との比較
H2: よくある質問（FAQ）

【まとめ・総評】
```

**コピーコンテンツ防止**
上位記事の見出し・文章をそのまま流用しない。ユーザーレビューの引用は出典を明記する。

## STEP 3: 本文執筆

### 文章の型

**PREP法**（良い点・悪い点の説明に使う）
```
P（Point）   — 「○○が優れています」と結論を先に
R（Reason）  — 理由「なぜなら〜」
E（Example） — 具体的な使用場面・数値・体験
P（Point）   — 「だから○○です」と再まとめ
```

**SDS法**（スペック・機能の説明に使う）
```
S（Summary） — 「この商品の最大の特徴は○○です」
D（Detail）  — 詳細スペック・機能の説明
S（Summary） — 「つまり○○な方に最適です」
```

### 読みやすい文章の4原則
1. **わかりやすさ** — 専門用語には必ず説明を加える
2. **結論先出し** — 各段落の最初に結論を書く
3. **短文化** — 一文は60字以内を目安にする
4. **箇条書き活用** — 3つ以上の比較要素は表にまとめる

### 信頼性を高める書き方
- 実体験ベースで書く（「〜と感じました」「〜でした」）
- **良い点・悪い点を必ず両方書く**（提灯記事は読者の信頼を失う）
- 数値・スペックは公式サイトを確認して正確に記載
- 「個人の感想です」「効果には個人差があります」を必要に応じて記載

**比較表の活用**
```
| 比較項目   | [本商品]  | 競合A    | 競合B    |
|-----------|---------|---------|---------|
| 価格      | ¥XX,000 | ¥XX,000 | ¥XX,000 |
| 機能A     | ◎       | ○       | △       |
| 機能B     | ○       | ◎       | ○       |
| コスパ    | ◎       | ○       | ○       |
```

### AI生成文の添削ポイント

| チェック項目 | 悪い例 | 良い例 |
|------------|-------|-------|
| 同じ文末の繰り返し | 〜です。〜です。〜です。 | 〜です。〜でした。〜といえます。 |
| 根拠のない断定 | 「最高の商品です」 | 「○○の点で優れています」 |
| 抽象的すぎる | 「非常に便利です」 | 「料理の時間が10分短縮できました」 |
| 誇大表現 | 「絶対に満足できます」 | 「○○な方には満足度が高いです」 |

## STEP 4: リード文・まとめ文

### リード文の書き方（200〜300字）
```
① こんな人に向けた記事（ターゲット明示）
② 結論を先出し（買うべきか否か）
③ 読み進める価値を伝える
```

**構成例**
```
「[商品名]の購入を検討中で、実際の使い心地を知りたい方へ。
結論から言うと、[ターゲット読者]には強くおすすめできる商品です。
この記事では[良い点・悪い点・比較情報]を正直にレビューしますので、
購入判断の参考にしてください。」
```

### まとめ・総評
```
【5段階評価】
- コスパ: ★★★★☆
- 機能性: ★★★★★
- デザイン: ★★★☆☆
- 使いやすさ: ★★★★☆
- 総合: ★★★★☆

【こんな人におすすめ】
- ○○な方
- ○○を重視する方

【こんな人には向かない】
- ○○な方
```

## STEP 5: 品質チェック

### AIっぽさ除去チェック
- [ ] 同じ文末表現が3回以上連続していない
- [ ] 「〜ということ」「〜となっています」などの冗長表現がない
- [ ] 単調な接続詞（「また」「さらに」）の繰り返しがない
- [ ] 体言止め・問いかけなどの表現バリエーションがある

### コピペチェック
- [ ] **CCDツール**でコピー率を確認する（クライアント基準に合わせる）
- [ ] Amazonレビュー・他サイトの文章をそのまま流用していない
- [ ] 引用する場合は「出典: 〇〇」と明記している

### ファクトチェック
- [ ] **Perplexity** または **Felo** でスペック・数値・商品情報を確認する
- [ ] 公式サイトで価格・スペックが最新かを確認する
- [ ] AIが生成した数値は必ず原典で裏取りする

### 信頼性・法令チェック
- [ ] 良い点と悪い点の両方が書かれている
- [ ] **薬機法**: 美容・健康商品で「治る」「絶対痩せる」「効果保証」などのNGワードを使っていない
  - NG例: 「〇〇が治る」「絶対痩せる」
  - OK例: 「〇〇が気になる方に」「すっきり感を実感」
- [ ] **景品表示法**: 実際より優れていると誤認させる表現がない
- [ ] **PR表記**: アフィリエイト案件の場合、冒頭に「PR」「広告」「プロモーション」と明記している
- [ ] 競合商品を不当に貶めていない

## 使用ツール一覧

| ツール | 用途 | 備考 |
|-------|------|------|
| **ラッコキーワード** | サジェスト・関連KW抽出 | 無料登録で月30回まで |
| **ChatGPT** | リサーチ・構成案・本文生成 | |
| **Perplexity** | ファクトチェック・商品情報収集 | 出典リンクで信頼性確認 |
| **Felo** | ファクトチェック補助 | Perplexityと併用 |
| **CCD** | コピペチェック | 1万字まで無料 |

---

## クラウドワークス納品時の注意点

- PR・広告案件の場合は必ず冒頭に「PR」「広告」「プロモーション」と明記する
- 薬機法・景品表示法に違反する表現は絶対に使わない
- Amazonリンク等は発注者の指示に従って挿入する
- 発注者が指定したレギュレーション（文体・禁止表現・文字数）を必ず確認してから執筆する
